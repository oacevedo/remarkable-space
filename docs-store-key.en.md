# App store client key

[中文](docs-store-key.md) · English

Keep the store index out of reach for anything outside Space: opening
`https://boangs.com/rmkit-space/index.json` in a browser returns 404, and only the on-device space-server
can fetch the content.

## What this gate blocks, and what it does not

**Blocks**: casually pasting the URL into a browser, crawlers walking in from links, reading the source
on GitHub to find the manifest. The same gate covers the index and the app zips, so stale copied links
also stop working.

**Does not block**: the binary is in users' hands, so `strings` can recover the key; the device is root,
so sniffing the network or just running `curl http://device:8080/space/store` returns the full index —
and that endpoint has to exist for the Discover page to work.

So it is a hurdle, not authorisation. If you actually need to defend against freeloading, verify an
activation code **at download time** (see the "Paid apps" section of the README). On that path the key
is not in the client's hands, which is the only way it can actually hold.

## Server side (nginx)

List the accepted keys in the `http` block — using a map so that during a rotation the old and new keys
can coexist while devices are upgraded, before the old row is removed:

```nginx
map $http_x_space_key $space_denied {
    default                                        1;   # no header / wrong key → deny
    "<current key>"                                0;   # current
    # "previous key"                               0;   # kept during transition; remove after all devices upgrade
}
```

In the `server` block, gate the index and the app zips:

```nginx
location = /rmkit-space/index.json {
    if ($space_denied) { return 404; }
}

location ~ ^/rmkit-space/.+\.zip$ {
    if ($space_denied) { return 404; }
}
```

**Return 404, not 403**: 403 tells the caller "there is something here but you cannot see it", 404 looks
like there is no file at all.

After changes: `nginx -t && nginx -s reload`.

## Release

The key **must never be committed** — this repo is open source, so a committed key means no gate at all.
Generate one with `python3 -c "import secrets; print(secrets.token_urlsafe(32))"`, store it somewhere of
your own (password manager, server `.env`), and inject it at build time:

```sh
make STORE_KEY=<current key>
```

Leaving it empty still builds — in that case space-server does not send the header, so **self-hosted
stores and local development are not affected**: anyone cloning the repo and pointing at their own index
URL still works.

## Rotating the key

No need to re-release to the device — add an environment variable to xochitl's drop-in to override the
compile-time value:

```ini
Environment=SPACE_STORE_KEY=<new key>
```

Order: **first add** the new key to the nginx map (old and new coexist) → ship a new build → wait for
devices to upgrade → remove the old row. Doing it the other way around makes the store disappear on every
not-yet-upgraded device.

## Verification

```sh
# Browser's view: expect 404
curl -s -o /dev/null -w '%{http_code}\n' https://boangs.com/rmkit-space/index.json

# Program's view: expect 200
curl -s -o /dev/null -w '%{http_code}\n' -H 'X-Space-Key: <key>' \
     https://boangs.com/rmkit-space/index.json
```

## Handshake mode (store-server)

The key above is the outer coarse filter. The real authorisation goes through a three-step handshake; the
server lives in another, private repo (`boangs/remarkable-space-store`) — see its README for deployment
and operations.

Turn on the handshake on the device:

```ini
# /etc/systemd/system/remarkable-space.service.d/10-store-api.conf
[Service]
Environment=SPACE_STORE_API=https://boangs.com/rmkit-space/api
```

**Use a drop-in, do not edit the main service file** — it is generated by `install.sh`, and reinstalling
would overwrite the edit. RMPP's `/etc` is a tmpfs overlay (upperdir in `/var/volatile`), so writes must
also go to the lower layer to survive a reboot:

```sh
mount --bind / /tmp/lowerroot && mount -o remount,rw /tmp/lowerroot
mkdir -p /tmp/lowerroot/etc/systemd/system/remarkable-space.service.d
cp /etc/systemd/system/remarkable-space.service.d/10-store-api.conf /tmp/lowerroot/etc/...
sync && umount /tmp/lowerroot
```

**Rollout order**: switch devices to the handshake and confirm they work, **then** 404 the static
`index.json` and zip direct links in nginx. Reversing the order would hide the store on every device that
has not yet switched.
